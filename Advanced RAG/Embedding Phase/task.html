Description

Depending on your specific use case, you may need to utilize more than one data store. You need to ensure that you are using the right data store for the right kind of data. A key point to remember is that, we don’t always need to use a vector store for RAG applications. If the information is highly structured, a relational database would be more appropriate. In other cases, graph, time series, and other types of databases might be more useful.

During retrieval, we can pass the LLM context from all relevant sources to ensure it has all the information needed to handle queries. For example, for a social media platform, you might use a vector store for internal guidelines, a graph database to map user relationships, and a NoSQL database for storing posts and interactions.

Now that we have documents containing the context and metadata we need, let’s begin by embedding them and storing them in a vector store. We will use PostgreSQL with the PGVector extension so that we can store the vectors in the same database as our other data. LangChain makes it easy to do this using the langchain-postgres package. You can learn more about it in the documentation.

You can run PostgreSQL with the pgvector extension using Docker by running the following command:

# for PowerShell, replace backslashes ('\') with backticks ('`') as line separators

docker run --name pgvector \
  -e POSTGRES_USER=hyper \
  -e POSTGRES_PASSWORD=hyper2025 \
  -e POSTGRES_DB=hyperdb \
  -p 5432:5432 \
  -v pgvector_data:/var/lib/postgresql/data \
  -d pgvector/pgvector:0.8.0-pg17

Of course, you need to have docker installed and running and also, ensure that port 5432 isn’t already in use. You can use any image tag for the database.

Once you’ve initialized the PostgreSQL database, place the connection string you used in your code in the .env file as follows:

PGVECTOR_CONNECTION_STRING="postgresql+psycopg://hyper:hyper2025@localhost:5432/hyperdb"

Great, now you have the PostgreSQL database up and running locally.

LangChain will automatically create the required tables for your vector database once integrated. Next, you need to store the orders in the database. Here, you need to import data from the sales data CSV file using your database client or SDKs and save it in a new table: orders. Verify that all tables are created successfully and contain the appropriate columns.

Objectives

In this stage, you need to do the following:

  • Embed the documents into a vector store using LangChain and PGVector (this will create two tables: langchain_pg_collection, and langchain_pg_embedding);

  • Load orders into the orders table (you may need to create this table beforehand or as part of the import process using your database client);

  • Your database should now contain three tables.
