Description

In RAG applications, the context you provide your LLM application plays a significant role. If the context is inadequate or irrelevant, you will most likely get irrelevant or hallucinated results. Conversely, the quality of your dataset as well as your splitting technique matters a lot.

Therefore, we need to check our knowledge bases as well as ensure that our text chunking techniques yield the best context for our RAG application. This means that we need to perform some preprocessing operations on our data before chunking. For instance, we can begin by removing unnecessary metadata from our dataset.

Also, we need to add some metadata with the chunks to describe them, such as the category that the chunk is relevant to and so on. This ensures that each chunk contains useful information for use later during generation.

In this project, we have two datasets. The first one is a dataset of recent orders for an e-commerce site. The next dataset contains how-to guides, FAQs, and policies scraped from the e-commerce company’s website. You need to download this noisy JSON dataset for processing.

Unfortunately, the scraped dataset contains a lot of unnecessary metadata. We would like to clean it up, retaining only the useful information. For instance, for FAQs, only the question and answer is relevant. For policies, only the policy is relevant. You need to clean the data and store it in a new knowledge_base_clean.json file that looks as follows:

Note that the new how-to key corresponds to the steps key in the original dataset.

Next, we need to create smaller chunks of the dataset. Each chunk should contain only 5 JSON entries of the same category. So, if a chunk contains FAQs, it should only contain question-answer pairs. Policies, how-tos, and support entries should also go into individual chunks.

Finally, we need to convert the chunks to LangChain documents to make embedding easier. In addition, we need to add some metadata to each document to describe it. The metadata should include a category as well as some tags for the whole chunk.

Chunks should be categorized and tagged as:

Category

Tags

faq

["frequently asked questions", "help", "general information"]

policy

["shipping", "returns", "privacy"]

how-to

["steps", "guides", "instructions"]

support

["customer support", "live chat", "contact methods"]

Therefore, a chunk should now look like that below:

support: You can contact our customer support team by phone at '<https://support.hypersite.org>' or by email at 'hello@hypersite.org'.
support: Our team is available 24/7 to assist you with any inquiries or issues you may have.
support: We offer live chat support on our website during our business hours.
{'category': 'support', 'tags': ['customer support', 'live chat', 'contact methods']}

Review LangChain’s API reference to learn more about creating documents and adding metadata.

Great. Now, the dataset is a bit better. We will use the metadata to filter for relevant results later. To pass the tests, you need to print the following:

  • The number of chunks for each category;

  • All documents that are categorized as support;

Objectives

To pass the stage, do the following:

  • Clean the dataset to fish out only the relevant information, which includes only question-answer pairs, policies, how-to steps, and support entries;

  • Store the cleaned dataset in a new knowledge_base_clean.json file;

  • When cleaning, rename the steps key to how-to;

  • Create chunks with a maximum of 5 entries containing entries of the same category and convert them to LangChain documents;

  • For each chunk, add metadata containing a category and tags;

  • Print the number of chunks you obtained for each category as follows:
