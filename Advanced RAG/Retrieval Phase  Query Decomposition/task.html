Description

Poor user queries can lead to irrelevant or misleading documents, which may degrade the quality of the generated output. This will cause the model to use the wrong context which will cause it to hallucinate. For this reason, we can apply various mechanisms to optimize the user’s query before sending it to the retriever. This involves:

  • Rewriting the query to make it more clear or add context;

  • Adding metadata or keywords to the query;

  • Expanding the query using related concepts;

  • Removing irrelevant words and ambiguity;

  • Formatting or translating the query to suit the retriever’s indexing mechanism.

In this stage, we will use LLM prompts to perform these transformations on the user’s query before passing it to the retriever. This ensures that when a user asks a question, our retriever can obtain the appropriate context to retrieve the most relevant documents.

Here, we need to create multiple queries from the user’s initial query. That is, from a user’s single query, the LLM should generate three questions that are similar to the original query. Specifically, we want each question to retrieve a different chunk in case the user asks multiple things. For example, a question like, “I need to cancel my order!”, may be further decomposed into multiple questions like:

  • Are there any policies I need to know before I cancel my order?

  • Will I receive a refund when I cancel my order?

  • How can I contact support to help me cancel my order?

  • Will I be refunded for shipping costs when I cancel my order?

By retrieving chunks for all these questions, we can provide the LLM with enough context to answer vague queries. We can also ask the LLM to remove irrelevant words to enhance retrieval further. Once we have multiple queries, we pass them to the retriever to obtain the top two (k=2) most relevant documents for each question. We'd then combine all these contexts and send them to the LLM to get the final answer.

To make it easier to parse the questions, instruct the LLM to output strictly JSON output without additional formatting or meta-text.

To pass this stage, print:

  • The generated questions from a user’s query;

  • The retrieved contexts and metadata for each rewritten query.

Using these techniques, we ensure that we retrieve the most appropriate context for use in our LLM application.

In some use cases, you may need to expand the user's query using the least-to-most prompting techniques, instead of decomposing it.

Objectives

Here is what you need to do at this stage:

  • Once a query is issued, prompt an LLM to generate 3 unique questions that decompose the user’s query to identify the user’s intent;

  • For each question, retrieve the top two documents that would best answer the question;

  • Print the three generated questions, and the context plus metadata retrieved from the vector store;

Examples

The greater-than symbol followed by a space (> ) represents the user input. Note that it's not part of the input.

Example 1: Enhanced questions

> I need to contact support
What is the best way to reach customer support for assistance?
Are there specific hours when customer support is available for contact?
What information do I need to provide when I contact support for help?
