Description

At this point, our retrieval mechanism is performing well. Great! We are getting the most appropriate chunks needed to answer any question a user may have. In basic RAG setups, the next thing would be to pass all the retrieved contexts (along with any chat history available) to the LLM. This might be okay if you are using a long context LLM, as everything would fit into the LLM's context window.

Unfortunately, not all retrieved contexts are needed to answer the query. In some cases, the LLM only needs the best one or two documents to answer the question sufficiently. Also, passing more documents means more tokens are used, which is more costly even though not all documents are needed.

This is where context-ranking techniques become useful. Here, you score the chunks by how relevant they are to the user's prompt. Only chunks with the highest scores are sent to the LLM. For instance, you might decide that only the top two chunks will be sent to the LLM. This ensures that you save costs while maintaining relevance in your RAG application.

There are various ways you can use to determine the best chunks. For example, you can prioritize chunks from internal documentation rather than information from a web search. Or, the most recent information should receive the highest priority. You can also use an LLM, fine-tuned models such as the cohere re-ranker, and other LLM evaluation techniques using libraries like Ragas to identify the most relevant chunks. You can use multiple re-ranking techniques for the best results.

In this stage, we will use Cohere's reranking endpoint to rank the retrieved contexts. You can get started using it for free by getting an API key from their website, but there will be some usage limits. The free trial should be enough for our use case. Below is an example of initializing Cohere reranker from the langchain_cohere package:

from langchain_cohere import CohereRerank

reranker = CohereRerank(
    model="rerank-english-v3.0",
    top_n=2,
    cohere_api_key=os.getenv("COHERE_API_KEY"),
)

Once you have the API key, retrieve the top 10 most relevant chunks from the vector store. Then, use the re-ranker to get the top 2 most relevant documents. Print the contents of the top 2 documents as ranked by Cohere.

If you'd like to learn more about using Cohere's re-ranker with your LangChain retriever, check out the LangChain documentation.

Objectives

These are the objectives for this stage:

  • Retrieve the 10 most relevant chunks from the vector store;

  • Send the chunks to Cohere's re-rank endpoints for scoring;

  • Print the contents of the ten most relevant chunks retrieved from the vector store;

  • Print the contents of the top 2 scored chunks along with their metadata.
